# AI 埋点助手 V2.1 · 多产品公开版

用于读取埋点表格、结合产品规范和经审核案例生成事件与参数，并导出带审核记录的 XLSX。

## 使用前须知

- 这是纯静态前端，没有服务器、账号系统、共享数据库或内置模型额度。
- 每位使用者自行配置模型地址、模型名称和 API Token。发布文件不包含任何模型 Token、私有接口地址或原产品历史案例。
- 产品规范、页面与按钮字典、案例及普通模型配置保存在当前浏览器的 localStorage；文字与图片 Token 按产品分别保存在 sessionStorage。它们不会跨浏览器或设备共享，也不会自动同步给其他同事。
- 上传的工作簿在浏览器中处理；点击生成或测试连接时会请求你配置的模型服务。生成会发送当前行相关文字、规范和参考案例，含图行还会发送对应截图。请确认你有权向该服务提供这些资料。
- 这是浏览器直连模型的部署方式，Token 对当前会话中的页面脚本和网络请求可见。请只在可信设备与接口上使用自己的凭据；不要将 Token、Authorization 或其他凭据填写到自定义 Headers（该项属于本地普通配置）。

## 快速开始

1. 打开网站，在“产品设置”填写产品名称、页面映射、点击与曝光规则、必填字段及规范；也可新增多个产品。公开版不预置原产品页面字典或历史案例。
2. 在“知识库”导入当前产品规范、案例，确认案例后才参与检索。案例与命名可按产品积累。
3. 打开“模型配置”，填写支持当前请求协议的模型接口、名称和自己的 Token，保存并测试连接。处理截图时需要支持图片输入的模型，可单独配置图片模型。
4. 上传 Excel 或其他支持的表格，点击“AI 自动补全”，逐条审核结果；“确认采用并记住”后积累经确认案例。
5. 导出 XLSX 与补全审核记录。

“示例数据”是人工编写的通用演示需求，不包含真实客户或产品数据；使用前仍需配置产品知识和模型。

## 接口与浏览器要求

网页使用 HTTPS。模型服务也应使用 HTTPS，并允许网页所在域名的浏览器跨域请求（CORS）。如果接口拒绝跨域访问、只允许服务端请求或不支持所选协议，GitHub Pages 无法替接口解除限制。不要通过关闭浏览器安全设置解决。

文字连接测试通过不代表图片能力可用。图片提取或图文理解失败的行会进入待处理，不应直接视为已确认。

## 表格范围

支持 XLS、XLSX、XLSM、XLSB、CSV、TSV、ODS 及可识别的 WPS 表格。导出统一为 XLSX；宏和部分复杂高级格式不保证保留。可提取并定位的普通内嵌图片按行关联，外部图片链接等不受支持。图片提取受工作簿内部结构限制，请保留原始文件并审核导出结果。

## 发布到 GitHub Pages

仓库只需要以下文件，无需构建、安装依赖或填写服务器环境变量：

```text
index.html
README.md
vendor/
  xlsx.full.min.js
  SheetJS-LICENSE.txt
```

1. 创建公开仓库，例如 `ai-tracking-assistant`。
2. 将上述文件放在仓库 `main` 分支根目录，保留 `vendor` 目录结构。不要上传整个开发工作区。
3. 打开仓库 Settings → Pages，Source 选择 Deploy from a branch，分支选择 main，目录选择 / (root)，保存。
4. 发布后地址通常为 `https://<GitHub用户名>.github.io/ai-tracking-assistant/`，最终以 Pages 设置页显示的地址为准。

参见 [GitHub Pages 官方入门](https://docs.github.com/en/pages/quickstart)。
